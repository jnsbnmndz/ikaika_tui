## Overview

This session extended the toolbox in three areas: the Windows window-shape module gained the ability to open the window at a planned size and restore a floor after a drag (`SizeGuard`), script repositories gained a post-clone setup step (`after-clone-command`) with derived tool requirements that Doctor now reports, and two ordering/lifecycle bugs were fixed in the script-action walk and in session relocation. Documentation in `CLAUDE.md` and `AGENT.md` was updated to match.

## Key Changes

**Window shape (`infrastructure/window_shape.py`, `presentation/tui_console.py`)**
- Added `WindowPlan`, `DEFAULT_PLAN`, `plan_for()`, `screen_size()` (work-area based, via `SystemParametersInfoW`) and `window_plan()`. `plan_for` reads the plan rather than the raw constants and shrinks both the start size and the floor to fit a short screen, keeping the aspect.
- Constants changed: `MIN_WIDTH` 846ΓåÆ900, `MIN_HEIGHT` 670ΓåÆ700; new `START_SIDE = 980`, `SCREEN_MARGIN = 30`, `RESIZE_ATTEMPTS = 2`, `SNAP_SLACK = 24`. `DEFAULT_PLAN` is `WindowPlan(START_SIDE+100, START_SIDE, ...)`.
- `AppWindow.resize()` reinstated (`SetWindowPos` with `SWP_NOMOVE|NOZORDER|NOACTIVATE`), reachable only through the new `SizeGuard`: `open_at_start_size()` asks once at mount (skipped when maximized, minimized, or already correct) and `hold()` asks only after a drag ends (`dragging()` via `GetAsyncKeyState`), capped at `RESIZE_ATTEMPTS` with the budget refilling once the window fits.
- `fits()`/`cramped()` now take a plan; `WINDOW_POLL_INTERVAL` 1.0 ΓåÆ 0.2 so the end of a drag is noticed; the header notice uses the plan's floor and is suppressed on a tick that just issued a resize.

**Script store setup (`templates/scripts.py`, `domain/script_config.py`, `ikaika.toml`)**
- New `after-clone-command` manifest key (`AFTER_CLONE`, `after_clone_from`). `_set_up()` runs it in the store after cloning, streams output into a bounded `deque` (`SETUP_TAIL = 12`) printed only on failure, and refuses any command containing an unresolved `${...}`.
- `_discard()` throws the store away on clone failure, setup failure, or cancellation (shielded so the removal survives the cancel).
- Tool requirements are now derived from commands: `split_command()`, `executable_of()` (skipping references and path-like tokens), `ScriptAction.executables`, `executables_from()`. Checked before setup commands run and before `run_action` stages a template; `ScriptCatalogue` carries `executables`.
- `ikaika.toml`: added `scaffold.scripts_root = "~/.ikaika/scripts"` and `[scripts.react_native] url`.

**Script-action walk ordering (`capabilities/script_actions.py`, `build.py`, `scaffold.py`)**
- The stale-store question is now asked *before* the "nothing of this kind" check, so a fall-back isn't chosen off a manifest already known to be out of date. `Ending.NOTHING` now carries the `notice`, which Build and Scaffold write to the console ahead of their own fall-back message.

**Session lifecycle (`presentation/tui_console.py`)**
